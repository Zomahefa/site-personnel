Chapitre 01Comprendre le portfolio

Le portfolio est une application Next.js qui sert une page unique, bilingue français/anglais, enrichie de quelques fonctions serveur : formulaire de contact, suivi d’audience, administration privée et assistant IA. Le contenu éditorial est statique ; seuls les messages et les visites passent par une base de données.

1.1 Ce que fait réellement le site

La page d’accueil raconte un parcours professionnel en six sections : projets, expertise, méthode, parcours, témoignages et contact. Autour de cette page, quatre capacités techniques tournent :

  • Un sélecteur de langue FR/EN qui change instantanément tous les textes sans recharger la page.
  • Un formulaire de contact qui écrit dans la table messages, avec repli vers l’e-mail si la base est indisponible.
  • Un compteur de visites qui écrit dans la table page_views, consultable dans /admin.
  • Un assistant IA qui répond aux questions sur le parcours à partir d’un prompt construit avec le contenu public du portfolio.
À retenir

Les projets, expériences, certifications et témoignages ne sont pas stockés en base. Ils sont écrits dans src/lib/content.ts, compilés avec le site et affichés immédiatement. La base ne contient que deux choses : les messages reçus et les visites.

1.5 Les trois vérités à retenir

01

Le contenu est centralisé

Une seule source : content.ts. Pas de base de données pour les projets, pas de CMS. C’est volontaire : simplicité, rapidité, versionnement Git.

02

La base est minimale

Deux tables : messages et page_views. Si Turso tombe, le site continue d’afficher le contenu ; le formulaire propose l’e-mail.

03

Les secrets restent dehors

Mot de passe admin, jeton Turso et clé IA vivent dans .env.local et dans Vercel. Jamais dans Git, jamais dans ce PDF.

Piège classique

Ne cherchez pas les projets dans la base de données ni dans un fichier JSON : ils sont dans src/lib/content.ts. Et ne modifiez pas src/types/index.ts en croyant changer les projets : ce fichier ne sert qu’au type Message de l’administration ; les types Project, Skill et Experience qu’il contient sont d’anciens types non utilisés par la page d’accueil.

3.4 Les routes API en détail

/api/messages — recevoir un message

  1. Lecture de l’IP via x-forwarded-for (premier segment) ou unknown.
  2. Limitation : 5 requêtes par 10 minutes et par IP (en mémoire de l’instance).
  3. Nettoyage : trim puis coupe à 120 (nom), 180 (e-mail), 30 (téléphone), 5 000 (message), 80 (type de projet).
  4. Validation : nom requis, e-mail regex, téléphone regex si fourni, message ≥ 10 caractères.
  5. Si un projectType est fourni, il est préfixé au message : Type de besoin : ….
  6. Insertion en base, réponse 201 avec le message créé.
  7. En cas d’erreur base : réponse 503 avec fallback: "email", et le formulaire propose un lien mailto: prérempli.

/api/visits — mesurer l’audience

  1. Limitation : 60 requêtes par 10 minutes et par IP ; au-delà, réponse 204 silencieuse.
  2. Filtrage des robots : bot, crawler, spider, headless, lighthouse.
  3. Chemin nettoyé (200 caractères), doit commencer par / et ne pas commencer par /admin.
  4. Référent (300 caractères), identifiant visiteur (80 caractères, anonymous par défaut).
  5. Pays lu dans x-vercel-ip-country ou cf-ipcountry.
  6. Appareil déduit du user-agent : Tablet, Mobile, Desktop.
  7. Insertion puis réponse 204, sans corps.

/api/assistant — répondre aux questions

  1. Rate limit : 25 requêtes par 10 minutes et par IP.

4.5 Le suivi d’audience

  1. VisitTracker s’exécute à chaque changement de pathname.
  2. Il ignore /admin.
  3. Il fabrique ou récupère un identifiant visiteur dans localStorage (zm_visitor_id).

7.2 Turso ou SQLite local ?

const isTurso = !!process.env.TURSO_DB_URL;

// Si TURSO_DB_URL est défini :
createClient({ url: TURSO_DB_URL, authToken: TURSO_DB_TOKEN })

7.4 L’administration

URL : /admin. La page est en noindex, nofollow et n’est pas listée dans le sitemap. Elle n’est pas liée depuis le site public.

Connexion

  1. Le formulaire envoie le mot de passe à /api/admin/login.
  2. La route limite à 6 tentatives par 15 minutes et par IP.
  3. Si ADMIN_PASSWORD n’est pas configuré : réponse 503 explicite.
  4. La comparaison se fait en temps constant (XOR caractère par caractère).
  5. En cas de succès, un cookie zm_admin_session est posé : HttpOnly, SameSite=Strict, Secure en production, durée 8 heures.
  6. Le jeton est expiration.signature, signature HMAC-SHA256 avec ADMIN_PASSWORD.

Onglet Messages

  • Liste les messages du plus récent au plus ancien.
  • Recherche locale sur le nom, l’e-mail et le message.
  • Affiche les coordonnées, le type de besoin et la date formatée en heure de Fianarantsoa.
  • Suppression unitaire avec confirmation.

7.7 Vie privée et données

  • Les messages contiennent des données personnelles (nom, e-mail, téléphone). Ne les exportez pas dans un dépôt public.
  • L’admin n’est pas indexé, mais il est accessible à toute personne qui connaît l’URL et le mot de passe.
  • Les visites ne stockent pas l’IP en base : elle sert uniquement au rate limiting en mémoire.
  • Le pays et l’appareil sont des données agrégées, pas des identifiants individuels.
  • Prévoyez une politique de conservation : supprimez les messages traités après un délai raisonnable.

Ordre de résolution du fournisseur

  1. Si AI_PROVIDER=google et GOOGLE_AI_API_KEY existe → Google.
  2. Si AI_PROVIDER=groq et GROQ_API_KEY existe → Groq.
  3. Sinon, si GROQ_API_KEY existe → Groq.
  4. Sinon, si GOOGLE_AI_API_KEY existe → Google.
  5. Sinon → réponse 503 not-configured, le widget affiche son message de repli.

8.3 Les modèles et paramètres

Groq (par défaut)

POST https://api.groq.com/openai/v1/chat/completions
model: GROQ_MODEL ?? "openai/gpt-oss-120b"
temperature: 0.35
max_tokens: 900
reasoning_effort: "low"
messages: [system, ...8 derniers messages]

reasoning_effort: "low" est important pour les modèles de raisonnement : sans cela, les tokens de réflexion peuvent consommer tout le budget et renvoyer une réponse vide. max_tokens: 900 laisse assez de place pour une réponse de 3 à 6 phrases.

Google Gemini (alternative)

POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent
model: GOOGLE_AI_MODEL ?? "gemini-2.5-flash"
temperature: 0.35
maxOutputTokens: 450
systemInstruction: prompt système
contents: messages (assistant → model)

8.8 Coût, confidentialité et limites

  • Chaque question consomme des tokens chez le fournisseur. Le paramètre max_tokens limite la dépense, mais ne la supprime pas.

  • Le prompt ne contient que des informations publiques. Il ne faut jamais y ajouter de données personnelles, de secrets ou de messages reçus.

11.15 Sauvegardes, rotation et coûts

Sauvegarde

turso db shell portfolio-zomahefa ".dump" > backup-portfolio-$(date +%F).sql

Téléchargez aussi une copie depuis le dashboard Turso si l’option est disponible. Conservez les sauvegardes hors du dépôt Git.

Rotation d’un secret

  1. Créez un nouveau jeton Turso (ou une nouvelle clé IA).
  2. Mettez-le dans Vercel → Environment Variables.
  3. Redéployez et testez.
  4. Révoquez l’ancien jeton dans Turso (dashboard ou CLI).

Pour ADMIN_PASSWORD, changez la valeur dans Vercel et redéployez. Toutes les sessions existantes seront invalidées.

Coûts et limites

  • Vercel et Turso proposent des paliers gratuits ; les limites et tarifs évoluent. Consultez les pages actuelles avant de dimensionner.
  • L’assistant IA est le poste de coût variable principal : chaque question consomme des tokens.
  • Les fonctions serverless ont une durée d’exécution limitée ; les appels IA doivent rester rapides.
  • Surveillez le nombre de messages et de visites : la base peut grossir, mais reste très légère pour un portfolio.

13.1 Les dix erreurs à éviter

  1. Modifier seulement le français. Le test de parité échouera, ou l’anglais affichera l’ancien texte.
  2. Chercher les projets en base. Ils sont dans content.ts.
  3. Inventer une valeur de visual. Le type n’accepte que trois valeurs ; ajoutez le rendu ou utilisez une galerie.
  4. Mettre une image externe sans remotePatterns. next/image la refusera.
  5. Utiliser un nom de fichier avec des espaces ou des majuscules. Vercel est sensible à la casse.
  6. Oublier de redéployer après un changement de variable. Les variables ne sont pas toujours rechargées par un simple push.
  7. Mettre l’URL avec un slash final. siteUrl le retire, mais autant écrire l’URL propre.
  8. Utiliser la base de production pour les previews. Les tests polluent les vrais messages et les vraies visites.
  9. Committer .env.local. Vérifiez git status avant chaque premier push.
  10. Croire qu’un test vert suffit. Le formulaire, l’admin et l’assistant doivent être testés à la main après déploiement.
