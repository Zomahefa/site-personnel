Chapitre 11Déploiement Vercel + Turso

Ce chapitre est la procédure complète, dans l’ordre, pour passer du dépôt local à un site public avec base de données distante. Comptez 20 à 30 minutes la première fois. Ne sautez pas l’étape d’initialisation de la base : c’est la cause n°1 des formulaires qui renvoient une erreur.

11.2 Prérequis

  • Un compte GitHub.
  • Un compte Vercel (gratuit suffit pour commencer).
  • Un compte Turso (gratuit suffit pour commencer).
  • Une clé API Groq ou Google AI Studio pour l’assistant.
  • Node.js 20+ et npm installés localement.
  • Le projet qui build en local.
  • Un nom de domaine, si vous ne voulez pas rester sur *.vercel.app.

11.3 Vérifications avant de déployer

Ne déployez jamais un état qui ne passe pas localement. Exécutez, dans l’ordre : 

npm ci
npm run lint
npm test
npm run build

Le build doit afficher les routes générées, dont /, /admin, /api/*, /sitemap.xml, /robots.txt et /manifest.webmanifest. S’il échoue, corrigez d’abord : Vercel échouera de la même manière.

Test de production local

Après npm run build, lancez npm run start et testez le formulaire, l’admin et l’assistant sur http://localhost:3000. C’est le meilleur moyen de détecter un problème de variables avant de déployer.

11.4 Pousser le code sur GitHub

git status
git add .
git commit -m "chore: préparation du déploiement"
git remote -v
git push origin main

Si le dépôt n’existe pas encore, créez-le sur GitHub (privé ou public), puis : 

git remote add origin https://github.com/<votre-compte>/<votre-depot>.git
git branch -M main
git push -u origin main
Avant le premier push

Vérifiez que .env.local, data/ et les fichiers *.db ne sont pas suivis. git status ne doit pas les afficher. Si un secret a déjà été commité, considérez-le comme compromis et changez-le.

11.5 Créer la base Turso

Option A — Via le tableau de bord (recommandé pour débuter)

  1. Créez un compte sur turso.tech.
  2. Dans le dashboard, créez une base de données, par exemple portfolio-zomahefa.
  3. Choisissez une région proche de vos visiteurs (par exemple Francfort pour l’Europe/Afrique de l’Est, ou la région proposée la plus proche).
  4. Copiez l’URL de connexion : elle commence par libsql://.
  5. Créez un jeton d’accès (token) pour cette base. Copiez-le immédiatement : il n’est affiché qu’une fois.

Option B — Via la CLI Turso

# Installation (macOS / Linux)
curl -sSfL https://get.tur.so/install.sh | bash

# ou avec Homebrew
brew install tursodatabase/tap/turso

# Connexion
turso auth signup
# ou
turso auth login

# Création de la base (exemple de région : fra)
turso db create portfolio-zomahefa --location fra

# Récupérer l'URL libsql://
turso db show portfolio-zomahefa --url

# Créer un jeton
turso db tokens create portfolio-zomahefa

# Vérifier
turso db list
Deux valeurs à conserver

URL : libsql://portfolio-zomahefa-<organisation>.turso.io
Token : une longue chaîne secrète.
Ne confondez pas avec l’URL HTTPS du dashboard. Le client libSQL attend le schéma libsql://.

11.6 Initialiser le schéma sur Turso

Vous pouvez le faire depuis votre machine, avant même de déployer Vercel. Cela vérifie que l’URL et le jeton fonctionnent. 

export TURSO_DB_URL="libsql://portfolio-zomahefa-...turso.io"
export TURSO_DB_TOKEN="le-jeton-secret"
npm run db:init

Sur Windows PowerShell :

$env:TURSO_DB_URL="libsql://..."
$env:TURSO_DB_TOKEN="..."
npm run db:init

Résultat attendu :

✓ Base initialisée
  cible        : Turso
  messages     : 0
  pages vues   : 0
  tables       : messages, page_views

Si vous obtenez une erreur d’authentification, le jeton est faux ou a été révoqué. S’il manque des droits, recréez un jeton en lecture/écriture sur cette base.

11.7 Importer le projet dans Vercel

  1. Connectez-vous à vercel.com.
  2. Cliquez sur Add New → Project.
  3. Importez le dépôt GitHub qui contient le portfolio.
  4. Vérifiez les réglages :
    • Framework Preset : Next.js (détecté automatiquement).
    • Root Directory : ./ (ou le sous-dossier si monorepo).
    • Build Command : npm run build.
    • Install Command : npm install (ou npm ci).
    • Output Directory : laisser vide (Next.js gère).
    • Node.js Version : 20.x ou 22.x.
  5. Ouvrez Environment Variables et ajoutez les variables de la section suivante.
  6. Cliquez sur Deploy.

Portée des variables

Ajoutez au minimum les variables à l’environnement Production. Si vous voulez que les Preview Deployments fonctionnent aussi, ajoutez-les à Preview — mais utilisez alors une base Turso de test, pas la base de production. Sinon, chaque preview écrira de vrais messages et de vraies visites.

Pourquoi NEXT_PUBLIC_ ?

Ce préfixe rend la variable lisible côté navigateur. Ici, ce n’est pas un secret : c’est simplement l’URL publique du site. Ne mettez jamais une clé API ou un mot de passe derrière un préfixe NEXT_PUBLIC_.
