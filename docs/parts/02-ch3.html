3.2 Le cœur : src/lib/content.ts

C’est le fichier le plus important du projet. Il contient :

  • siteUrl : l’URL publique, lue depuis NEXT_PUBLIC_SITE_URL avec un domaine par défaut.
  • site : les informations neutres, identiques en français et en anglais (nom, e-mail, téléphone, réseaux, CV, coordonnées, fuseau).
  • Les types de toutes les structures : FeaturedProject, ArchiveProject, Practice, StackLevel, QaCategory, Experience, Certification, Testimonial, SiteContent…
  • const fr: SiteContent : tout le contenu français.
  • const en: SiteContent : tout le contenu anglais, avec la même structure.
  • contentByLocale, defaultContent, getContent(locale) et mailtoForProject(title).

Ordre réel du fichier, de haut en bas :

siteUrl
site
types (lignes ~24 à ~403)
const fr: SiteContent = { ... }      # contenu français
const en: SiteContent = { ... }      # contenu anglais
export const contentByLocale = { fr, en }
export const defaultContent = fr
export function getContent(locale)
export function mailtoForProject(title)
Ne pas se fier aux numéros de ligne

Le fichier fait plus de 2 000 lignes et bouge à chaque ajout. Utilisez les ancres textuelles : const fr: SiteContent, const en: SiteContent, featuredProjects:, archive:, about:, testimonials:.

3.4 Les routes API en détail

/api/messages — recevoir un message

  1. Lecture de l’IP via x-forwarded-for (premier segment) ou unknown.
  2. Limitation : 5 requêtes par 10 minutes et par IP (en mémoire de l’instance).
  3. Nettoyage : trim puis coupe à 120 (nom), 180 (e-mail), 30 (téléphone), 5 000 (message), 80 (type de projet).
  4. Validation : nom requis, e-mail regex, téléphone regex si fourni, message ≥ 10 caractères.
  5. Si un projectType est fourni, il est préfixé au message : Type de besoin : ….
  6. Insertion en base, réponse 201 avec le message créé.
  7. En cas d’erreur base : réponse 503 avec fallback: "email", et le formulaire propose un lien mailto: prérempli.

/api/visits — mesurer l’audience

  1. Limitation : 60 requêtes par 10 minutes et par IP ; au-delà, réponse 204 silencieuse.
  2. Filtrage des robots : bot, crawler, spider, headless, lighthouse.
  3. Chemin nettoyé (200 caractères), doit commencer par / et ne pas commencer par /admin.
  4. Référent (300 caractères), identifiant visiteur (80 caractères, anonymous par défaut).
  5. Pays lu dans x-vercel-ip-country ou cf-ipcountry.
  6. Appareil déduit du user-agent : Tablet, Mobile, Desktop.
  7. Insertion puis réponse 204, sans corps.

/api/assistant — répondre aux questions

  1. Rate limit : 25 requêtes par 10 minutes et par IP.
  2. Résolution du fournisseur : AI_PROVIDER explicite si la clé existe, sinon Groq, sinon Google, sinon 503.
  3. Nettoyage : garde les 8 derniers messages, tronque chaque contenu à 1 200 caractères, ignore les rôles invalides.
  4. Construction du prompt système via buildAssistantSystemPrompt().
  5. Appel du fournisseur, réponse JSON { reply, provider }, en-tête no-store.

Le seul fichier à retenir

Pour 90 % des mises à jour de contenu, vous n’ouvrirez que src/lib/content.ts. Pour les images et le CV, vous déposerez un fichier dans public/. Pour le SEO global, vous ouvrirez src/app/layout.tsx. Le reste sert surtout au fonctionnement.
