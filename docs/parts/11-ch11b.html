11.9 Déployer

  1. Cliquez sur Deploy. Vercel installe les dépendances, lance npm run build, puis publie.
  2. Suivez les logs de build. Une erreur TypeScript ou un module manquant apparaît ici.
  3. À la fin, Vercel fournit une URL du type https://portfolio-xxxx.vercel.app.
  4. Ouvrez cette URL. Le site doit s’afficher même avant d’ajouter un domaine personnalisé.
  5. Si NEXT_PUBLIC_SITE_URL pointe déjà vers le domaine final, les métadonnées seront correctes. Sinon, mettez-la à jour et redéployez.

Variante CLI Vercel (optionnelle)

npm i -g vercel
vercel login
vercel
vercel --prod

La CLI guide la création du projet et permet d’ajouter des variables : 

vercel env add ADMIN_PASSWORD production
vercel env add TURSO_DB_URL production
vercel env add TURSO_DB_TOKEN production
vercel env add GROQ_API_KEY production
vercel env add NEXT_PUBLIC_SITE_URL production

Après un changement de variable, relancez vercel --prod ou cliquez sur Redeploy dans le dashboard.

11.10 Vérifier le déploiement

1. La page et les en-têtes

curl -I https://votre-domaine.tld
curl -I https://votre-domaine.tld/admin
curl -s https://votre-domaine.tld/robots.txt
curl -s https://votre-domaine.tld/sitemap.xml
  • La page d’accueil répond 200.
  • /admin répond 200 mais contient noindex.
  • robots.txt exclut /admin/ et /api/.
  • sitemap.xml contient l’URL finale, pas localhost.
  • Les en-têtes content-security-policy, strict-transport-security, x-frame-options sont présents.

2. Le contenu

  • Le hero affiche le bon nom, les bons rôles, les bonnes statistiques.
  • Les projets vedettes et l’archive sont complets.
  • Les images se chargent (pas de 404 dans la console).
  • Le CV et les PDF de certification s’ouvrent.
  • La bascule FR/EN fonctionne et persiste après rechargement.

3. Le formulaire et l’admin

  1. Envoyez un message de test avec une vraie adresse e-mail.
  2. Vérifiez l’écran de succès.
  3. Connectez-vous à /admin avec ADMIN_PASSWORD.
  4. Le message doit apparaître dans l’onglet Messages.
  5. Supprimez-le après vérification.
Si le formulaire échoue

Le formulaire affiche un lien mailto: de repli. Cela signifie que l’API n’a pas pu écrire en base. Vérifiez TURSO_DB_URL, TURSO_DB_TOKEN, puis les logs Vercel (Functions → Logs). Lancez npm run db:init avec les mêmes valeurs pour isoler le problème.

4. Les visites

  1. Ouvrez le site dans un navigateur normal (pas en navigation privée avec bloqueur).
  2. Naviguez entre les ancres ou rechargez la page.
  3. Dans /admin → Audience, vérifiez que le total augmente.

Les robots, /admin et les requêtes trop fréquentes ne sont pas comptés. Si le compteur reste à zéro, vérifiez que /api/visits répond 204 dans l’onglet Réseau et que la base est accessible.

5. L’assistant

curl -s https://votre-domaine.tld/api/assistant \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"Quels sont tes projets ?"}]}'

Attendu : {"reply":"...","provider":"groq"}. Si vous obtenez not-configured, la clé n’est pas dans l’environnement Production ou le déploiement n’a pas été refait après l’ajout.

6. Le partage social et le SEO

  • Ouvrez https://www.linkedin.com/post-inspector/ et testez l’URL.
  • Vérifiez que l’image og-image.png apparaît (1200×630).
  • Dans Google Search Console, ajoutez la propriété et soumettez le sitemap.
  • Testez https://votre-domaine.tld/manifest.webmanifest.

11.11 Ajouter un domaine personnalisé

  1. Dans Vercel : Project → Settings → Domains.
  2. Ajoutez votre-domaine.tld et, si besoin, www.votre-domaine.tld.
  3. Vercel affiche les enregistrements DNS à créer chez votre registrar :
    • A vers l’IP Vercel pour le domaine racine, ou
    • CNAME vers cname.vercel-dns.com pour un sous-domaine.
  4. Attendez la propagation DNS (quelques minutes à quelques heures).
  5. Mettez NEXT_PUBLIC_SITE_URL à https://votre-domaine.tld (sans slash final).
  6. Redéployez : les métadonnées sont générées au build.
  7. Vérifiez le canonical, le sitemap, le robots et le JSON-LD.
Deux domaines, un seul canonical

Si zo-mahefa-it.vercel.app et votre domaine personnalisé répondent tous les deux, choisissez le domaine final comme NEXT_PUBLIC_SITE_URL et redirigez l’autre vers celui-ci (Vercel permet de définir un domaine principal). Sinon, les moteurs voient deux URLs pour le même contenu.

11.12 Mettre à jour le site

Une fois le projet connecté à GitHub, le flux est automatique :

  1. Modifiez le contenu ou le code en local.
  2. Lancez npm test et npm run build.
  3. Commit et push sur la branche main.
  4. Vercel détecte le push et lance un nouveau déploiement.
  5. Vérifiez le déploiement dans l’onglet Deployments.
git add .
git commit -m "content: mise à jour du projet X"
git push origin main

Pour les variables d’environnement, le flux est différent : modifiez-les dans Vercel, puis cliquez sur Redeploy. Un simple push ne suffit pas toujours à recharger une variable modifiée.

11.13 Revenir à une version précédente

  1. Vercel → Deployments.
  2. Repérez le dernier déploiement qui fonctionnait.
  3. Menu … → Promote to Production (ou Rollback selon l’interface).
  4. Vérifiez le site.
  5. Corrigez le code en local, puis poussez un nouveau commit.

Le rollback Vercel est immédiat mais ne corrige pas Git : la prochaine publication reprendra le dernier commit. Pour un retour propre, faites aussi un git revert.

11.15 Sauvegardes, rotation et coûts

Sauvegarde

turso db shell portfolio-zomahefa ".dump" > backup-portfolio-$(date +%F).sql

Téléchargez aussi une copie depuis le dashboard Turso si l’option est disponible. Conservez les sauvegardes hors du dépôt Git.

Rotation d’un secret

  1. Créez un nouveau jeton Turso (ou une nouvelle clé IA).
  2. Mettez-le dans Vercel → Environment Variables.
  3. Redéployez et testez.
  4. Révoquez l’ancien jeton dans Turso (dashboard ou CLI).

Pour ADMIN_PASSWORD, changez la valeur dans Vercel et redéployez. Toutes les sessions existantes seront invalidées.

Coûts et limites

  • Vercel et Turso proposent des paliers gratuits ; les limites et tarifs évoluent. Consultez les pages actuelles avant de dimensionner.
  • L’assistant IA est le poste de coût variable principal : chaque question consomme des tokens.
  • Les fonctions serverless ont une durée d’exécution limitée ; les appels IA doivent rester rapides.
  • Surveillez le nombre de messages et de visites : la base peut grossir, mais reste très légère pour un portfolio.

11.16 Checklist de mise en production

  • Build local vert (npm run build).
  • Tests verts (npm test).
  • Dépôt GitHub à jour, sans secret.
  • Base Turso créée, URL et jeton récupérés.
  • npm run db:init exécuté sur Turso.
  • Projet Vercel importé.
  • Toutes les variables Production ajoutées.
  • Déploiement réussi.
  • Page d’accueil, admin, formulaire, visites et assistant testés.
  • Domaine ajouté et NEXT_PUBLIC_SITE_URL mis à jour.
  • Redéploiement après changement d’URL.
  • Sitemap, robots, canonical et Open Graph vérifiés.
  • Message de test supprimé, visites de test nettoyées si besoin.
