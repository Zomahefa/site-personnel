Chapitre 05Modifier les contenus

Toutes les recettes de ce chapitre suivent le même principe : ouvrir src/lib/content.ts, repérer la clé, modifier la version française et la version anglaise, puis lancer les tests. Aucune base de données, aucun CMS, aucune interface d’administration pour le contenu éditorial.

Procédure standard
  1. Ouvrir src/lib/content.ts.
  2. Chercher la clé (ex. featuredProjects:).
  3. Modifier le bloc dans const fr, puis le même bloc dans const en.
  4. Lancer npm test : il vérifie la parité des structures et l’absence de texte vide.
  5. Lancer npm run build pour vérifier TypeScript et la compilation.
  6. Commit + push : Vercel redéploie automatiquement.

Ces informations sont neutres : elles ne sont pas traduites. Elles vivent dans l’objet site, tout en haut de content.ts.

ChampOù il apparaît
name, shortName, initialsHeader, hero, footer, métadonnées, JSON-LD.
emailContact, footer, prompt IA, liens mailto:.
phone, phoneHrefContact, footer, témoignages (téléphone séparé), JSON-LD.

Cohérence du téléphone

phone est la version affichée ; phoneHref est la version tel: sans espaces. Si vous changez l’un, changez l’autre. Le JSON-LD de layout.tsx contient aussi le numéro en dur (+261385442252) : pensez à le mettre à jour.

5.2 Le hero et les statistiques

Le bloc hero existe en français et en anglais. Les champs importants : 

hero: {
  eyebrowLeft: "PORTFOLIO / ÉDITION 2026",
  eyebrowCenter: "FIANARANTSOA, MADAGASCAR · UTC+3",
  eyebrowRight: "DISPONIBLE POUR COLLABORER",
  kicker: "Ingénieur logiciel",
  title: {
    sr: "Zo Mahefa RANAIVO — Développeur web & mobile, ...",
    line1: "Du premier",
    line2Em: "commit",
    line2After: " au",
    line3Em: "dernier",
    line3After: " test.",
  },
  roleLabel: "RÔLE_",
  intro: "Je conçois des applications web et mobiles, ...",
  primaryCta: "Voir mes preuves",
  secondaryCta: "Parler d'un projet",
  cvCta: "CV PDF",
  stats: [
    { value: 9, pad: 2, label: "projets documentés" },
    { value: 3, pad: 2, label: "pôles d'expertise" },
    { value: 8, pad: 2, label: "dépôts publics" },
    { value: 48, prefix: "<", suffix: "h", label: "délai de réponse" },
  ],
}
  • title.line2Em et line3Em sont les mots mis en italique. line2After et line3After sont le texte qui suit.
  • title.sr est le titre complet pour les lecteurs d’écran et le SEO. Il doit rester descriptif.
  • stats[].value est le nombre cible. pad: 2 affiche 09 au lieu de 9.
  • prefix et suffix sont optionnels : < + 48 + h donne <48h.
  • roles (au niveau racine de SiteContent) alimente l’animation des rôles sous le titre.
Règle de crédibilité

Ne mettez dans les statistiques que des chiffres que vous pouvez défendre : nombre de projets réellement documentés, nombre de dépôts publics, nombre de pôles. Évitez les pourcentages inventés.

5.3 Les titres et intros de sections

Le bloc sections contient six objets : projects, expertise, method, about, testimonials, contact. Chacun a index, label, title et intro. 

sections: {
  projects: {
    index: "01",
    label: "Travaux sélectionnés",
    title: "Des preuves, pas des promesses.",
    intro: "Trois projets, trois problèmes réels. ...",
  },
  // ...
}

Les index 01 à 06 sont affichés dans les titres. Si vous ajoutez une section, mettez à jour les index, le menu nav et l’ordre dans src/app/page.tsx.

5.4 Modifier un projet vedette

Les projets vedettes sont dans featuredProjects. Chaque objet contient les champs suivants :

ChampRequisRôle
idOuiIdentifiant unique, en kebab-case. Sert de clé React.
indexOuiNuméro affiché (01, 02, 03…).
title, subtitleOuiNom du projet et accroche courte.
year, categoryOuiAnnée et catégorie affichées dans les métadonnées.
summaryOuiRésumé en une phrase.
contextOuiCadre du projet (licence, freelance, stage…).
problem, role, outcomeOuiLes trois blocs de l’étude de cas.
stackOuiTableau de technologies affichées en tags.
visualOuiincident, erp ou pipeline.
galleryNonCaptures d’écran. Si présent, remplace le schéma SVG par un carrousel.
repo, demo, demoLabelNonLiens vers le code et la démo.
privateCodeNonSi true, affiche « Étude de cas sur demande » avec un lien mailto.

Exemple réel : Signaleo

{
  id: "signaleo",
  index: "01",
  title: "Signaleo",
  subtitle: "Signalement de pannes · terrain & supervision",
  year: "2025",
  category: "Web app / DevOps",
  summary: "Un outil unique pour signaler une panne, la localiser et suivre sa résolution en temps réel.",
  context: "Projet de licence L3, conduit du cadrage jusqu'à la mise en production et à la supervision.",
  problem: "Les interventions étaient suivies sans vue d'ensemble : statuts dispersés, faible traçabilité...",
  role: "Conception du parcours de signalement, tableau de bord d'administration, suivi des statuts...",
  outcome: "Une application déployée et observée, avec un flux de livraison reproductible...",
  stack: ["React", "Django", "MySQL", "Docker", "GitHub Actions", "Nginx", "Prometheus", "Grafana"],
  visual: "incident",
  gallery: [
    {
      src: "/projects/signaleo-signalement.png",
      alt: "Capture de l'écran de signalement d'une panne sur Signaleo",
      label: "Signalement d'une panne",
    },
  ],
  repo: "https://github.com/Zomahefa/gestion-de-panne-devops",
  demo: "https://signaleo.onrender.com/",
  demoLabel: "Consulter la démo",
}
Le champ visual est typé

ProjectVisualKind n’accepte que "incident", "erp" ou "pipeline". Si vous inventez une valeur comme "mobile", TypeScript refusera le build. Pour un nouveau type, il faut modifier le type dans content.ts et ajouter le rendu correspondant dans src/components/site/project-visual.tsx. Le plus simple reste de fournir une gallery : le carrousel remplace le schéma.

5.5 Modifier l’archive

L’archive est le bloc archive. Chaque entrée est volontairement courte : 

archive: {
  kicker: "ARCHIVE / 06",
  title: "Autres projets & labs",
  copy: "Le reste du terrain : desktop, réseau, systèmes et projets académiques...",
  footerNote: "ZÉRO LIEN MORT — LES PROJETS PRIVÉS SONT SIGNALÉS",
  allRepos: "Tous mes dépôts publics",
  projects: [
    {
      title: "Gestion de station essence",
      category: "Desktop · JavaFX",
      year: "2024",
      stack: "JavaFX · PostgreSQL",
      href: "https://github.com/Zomahefa/Gestion-de-station-essence",
      label: "Code",
    },
    {
      title: "Administration Linux & Windows Server",
      category: "Systèmes · ENI",
      year: "2023 — 2024",
      stack: "Active Directory · Bash · iptables",
      label: "Lab",
    },
  ],
}
  • Si href est présent, la ligne est un lien et affiche « Code ».
  • Si href est absent, la ligne est statique et affiche label (« Lab », « Labs »…).
  • kicker contient le nombre affiché ; pensez à l’ajuster si vous ajoutez des lignes.
