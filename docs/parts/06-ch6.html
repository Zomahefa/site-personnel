Chapitre 06Ajouter un projet

Il existe deux niveaux de mise en avant : le projet vedette, qui occupe une grande ligne avec étude de cas et visuel, et le projet d’archive, qui tient sur une ligne compacte. Les deux se modifient dans content.ts, jamais en base.

6.1 Ajouter un projet vedette — pas à pas

Étape 1 — Préparer les images

Déposez les captures dans public/projects/. Utilisez des noms courts, en minuscules, sans espaces : 

public/projects/
├── mon-projet-tableau-de-bord.png
├── mon-projet-liste.png
└── mon-projet-detail.png
  • Format conseillé : PNG ou WebP, largeur 1 200–1 600 px.
  • Évitez les captures avec des données personnelles réelles (noms, e-mails, numéros).
  • Si vous n’avez pas de capture, utilisez un visual existant : incident, erp ou pipeline.

Étape 2 — Ajouter l’objet en français

Dans const fr, cherchez featuredProjects: [. Ajoutez votre objet à l’endroit où vous voulez qu’il apparaisse. Pour le mettre en premier, placez-le juste après le crochet ouvrant. 

{
  id: "mon-projet",
  index: "04",
  title: "Mon projet",
  subtitle: "Gestion de stock · PME",
  year: "2026",
  category: "Web app / Fullstack",
  summary: "Une application pour suivre les stocks et les ventes en temps réel.",
  context: "Projet freelance réalisé pour une PME locale.",
  problem: "Les stocks étaient suivis sur tableur, avec des ruptures et des doublons.",
  role: "Cadrage, modélisation des données, API, interface et déploiement.",
  outcome: "Un tableau de bord unique, des alertes de seuil et une mise en production reproductible.",
  stack: ["Next.js", "TypeScript", "PostgreSQL", "Docker"],
  visual: "erp",
  gallery: [
    {
      src: "/projects/mon-projet-tableau-de-bord.png",
      alt: "Tableau de bord du projet Mon projet avec les indicateurs de stock",
      label: "Tableau de bord",
    },
    {
      src: "/projects/mon-projet-liste.png",
      alt: "Liste des produits et seuils d'alerte",
      label: "Liste des produits",
    },
  ],
  repo: "https://github.com/Zomahefa/mon-projet",
  demo: "https://mon-projet.vercel.app/",
  demoLabel: "Voir la démo",
},
Les champs obligatoires

id, index, title, subtitle, year, category, summary, context, problem, role, outcome, stack et visual sont requis par le type FeaturedProject. Un oubli fait échouer npm run build avec un message TypeScript explicite.

Étape 3 — Ajouter le même objet en anglais

Dans const en, cherchez à nouveau featuredProjects: [. Ajoutez le même objet, avec les textes traduits. Conservez strictement les mêmes id, index, year, stack, chemins d’images, liens et visual.

Étape 4 — Ajuster les index et les compteurs

Si vous insérez le projet au milieu, renumérotez les index des projets suivants ("01", "02", "03"…) dans les deux langues. Pensez aussi aux statistiques du hero (hero.stats, « projets documentés ») et au kicker de l’archive si le nombre de projets change.

Étape 5 — Vérifier

npm test
npm run build
npm run dev

Ouvrez http://localhost:3000, vérifiez le projet en français, basculez en anglais, testez le carrousel au clavier (flèches gauche/droite), vérifiez les liens de démo et de code. Sur mobile, vérifiez que les images ne débordent pas.

6.2 Ajouter un projet d’archive

C’est plus simple : une ligne, pas d’image, pas d’étude de cas. Dans archive.projects, ajoutez : 

{
  title: "Mon projet d'archive",
  category: "Desktop · JavaFX",
  year: "2026",
  stack: "JavaFX · SQLite",
  href: "https://github.com/Zomahefa/mon-projet-archive",
  label: "Code",
},
  • href : si présent, la ligne est cliquable et affiche « Code ».
  • label : affiché seulement si href est absent. Utilisez « Lab », « Labs » ou « Projet privé ».
  • Mettez à jour archive.kicker (« ARCHIVE / 07 ») et, si besoin, le texte copy.

6.3 Cas particuliers

Projet sans dépôt public

N’ajoutez pas repo. Ajoutez privateCode: true : le lien « Étude de cas sur demande » apparaîtra et ouvrira un e-mail prérempli avec le nom du projet. 

privateCode: true,
demo: "https://demo.example.com/",
demoLabel: "Voir la démo",

Projet sans capture d’écran

Utilisez un visual existant. Les trois schémas sont définis dans src/components/site/project-visual.tsx :

ValeurUsage
incidentSignalement, supervision, incidents, workflow terrain.
erpTableaux de bord, gestion, stocks, ventes, trésorerie.
pipelineCI/CD, tests, logs, alertes, infrastructure.

Créer un nouveau type de visuel

  1. Dans content.ts, ajoutez la valeur à l’union : 
    export type ProjectVisualKind = "incident" | "erp" | "pipeline" | "mobile";
  2. Dans src/components/site/project-visual.tsx, ajoutez le rendu correspondant (SVG, blocs, textes).
  3. Utilisez la nouvelle valeur dans vos objets FR et EN.
Alternative plus simple

Si vous n’avez qu’une capture, utilisez gallery avec un seul élément : le carrousel s’affiche en mode « aperçu », sans autoplay. C’est souvent plus convaincant qu’un schéma générique.

Images externes

next.config.ts autorise les images locales (localPatterns: [{ pathname: "/**" }]) mais ne déclare aucun remotePatterns. Une URL externe dans gallery[].src sera refusée par next/image. Le plus sûr est de télécharger l’image dans public/projects/. Sinon, ajoutez le domaine dans next.config.ts : 

images: {
  // ...
  remotePatterns: [
    { protocol: "https", hostname: "images.example.com" },
  ],
},

6.4 Checklist d’ajout de projet

  • Images déposées dans public/projects/, noms en minuscules.
  • Objet ajouté dans featuredProjects côté fr.
  • Objet identique ajouté côté en (mêmes id, index, stack, liens, images).
  • Index des autres projets renumérotés si nécessaire.
  • Statistiques du hero et archive.kicker à jour.
  • npm test et npm run build passent.
  • Vérification visuelle desktop + mobile + FR/EN.
  • Liens de démo et de code testés.
  • Commit et push : déploiement Vercel automatique.
